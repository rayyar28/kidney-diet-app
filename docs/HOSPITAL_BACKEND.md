# 後端改成「醫院主機版」：改了什麼、為什麼

> 2026-10-18　依照醫院端提供的環境資料（《系統資訊.md》與主機環境報告）調整。
> 本文件不寫出主機 IP、醫院名稱與電腦名稱：repo 是公開的。實際值請看醫院端的《系統資訊.md》。

**一句話版本**：拿掉 Docker 與 Caddy，改成後端直接在醫院那台 Windows 電腦上用醫院的憑證提供 HTTPS；
病人帳號改成只有研究編號、只能由衛教師建立；整個後端做成一個「解壓縮就能跑、不用網路、不用系統管理員」
的安裝包，操作方式跟醫院原本那套一樣是編號 1～10 的腳本。

---

## 先看結論

| | 以前（Docker 方案） | 現在（醫院主機版） | 為什麼要改 |
|---|---|---|---|
| 怎麼跑 | Docker Desktop + Caddy + 容器 | 後端直接跑，隨附 `node.exe` | 那台電腦**裝不了 Docker**（不是系統管理員、沒有網路） |
| HTTPS | Caddy 自己當 CA、自己簽憑證 | 用**醫院 CA 簽的** `server.crt` | 醫院已經有一套 CA，不能再多一張 |
| Port | 443 + 8080 | **9443** | 8080 在那台電腦**不能用**；9443 是資訊室申請的那一個 |
| 安裝 | `docker pull`、`npm install` | 解壓縮 | 那台電腦連不到 npm、PyPI |
| 病人帳號 | email + 姓名，**任何人都能註冊** | **研究編號**，只有衛教師能建 | 醫院規定只用研究編號；開放註冊等於讓路人上傳到研究資料庫 |
| 電腦睡著 | 沒處理 | 後端執行期間不讓它睡 | 那台是診間電腦，閒置會睡，睡了病人就傳不上來 |
| 操作 | `docker compose …` 指令 | `1_check_env.bat` … `10_verify_closed.bat` | 跟醫院原本那套同一個習慣，同一個人能操作兩套 |

原本那套醫院的 FastAPI 後端也是用 9443。**我們的後端是取代它**，不是並存（一台主機一個服務、資訊室只開一個 port）。

---

## 一、醫院的環境告訴我們什麼

原本的部署手冊（`DEPLOY_HOSPITAL.md`）是在還不知道主機實際狀況時寫的，預設可以裝 Docker。
拿到醫院端的環境資料之後，發現下面這幾件事讓原計畫**根本跑不起來**：

| 事實 | 在哪裡看到 | 對原計畫的影響 |
|---|---|---|
| 登入的帳號**不是系統管理員** | 環境報告第 1 節 | Docker Desktop 安裝需要管理員 → 裝不了 |
| **連不到 PyPI、沒有 proxy** | 環境報告第 6、7 節 | 同理也連不到 npm、Docker Hub → `npm install`、`docker pull` 都不行 |
| 8443、**8080**、8000 被 Windows 保留或佔用 | 系統資訊第 2 節 | Caddy 原本開 8080 給病人下載 APK → 不能用 |
| 已經有一張**醫院自建的 CA**，`ca.key` 離線保管 | 系統資訊第 3 節 | Caddy 會自己再生一張 CA → 兩張 CA，App 只能信任其中一張 |
| 後端**直接提供 HTTPS**，沒有反向代理 | 系統資訊第 1 節 | 多一層 Caddy 沒有必要 |
| 主機支援 **S3 睡眠** | 環境報告第 9 節 | 閒置一陣子就睡，睡著時病人怎麼按都傳不上來 |
| 更新方式是「**解壓縮覆蓋**」，而且**曾經整個資料夾遺失**、只好重建 CA | 系統資訊第 3、8 節 | 程式跟資料放在一起，很危險 |
| 病人身分**只用研究編號**，不存姓名或病歷號 | 系統資訊第 1、6 節 | 我們存 email 與姓名，跟送資訊室的申請書不一致 |
| 防火牆跳出「允許存取網路」時**按取消會建立封鎖規則** | 系統資訊第 8 節 | 封鎖規則會蓋過允許規則，手機一定連不上 |

結論：**Docker 方案在這台電腦上不可行**，要改成「在 Windows 上原生執行」，而且整個後端要事先包好、帶過去解壓縮就能用。

## 二、改了什麼

### 1. 不用 Docker、不用 Caddy：後端自己提供 HTTPS

```
以前：手機 ──443──▶ Caddy（自己當 CA）──▶ Docker 裡的後端 ──▶ 資料庫 volume
現在：手機 ──9443─▶ 後端（用醫院 CA 簽的憑證）──────────────▶ data\kidney.db
```

後端多了幾個設定值（都寫在主機上的 `config\kidney.env`，由 `4_setup.bat` 自動產生）：

| 設定 | 作用 |
|---|---|
| `TLS_CERT_FILE` / `TLS_KEY_FILE` | 有設就直接提供 HTTPS；沒設就跟以前一樣是 HTTP（開發機、Render 都不受影響） |
| `PORT=9443` | 醫院主機用的 port |
| `PUBLIC_HOST` | 手機要連的 IP，啟動時用來檢查憑證是不是簽給它 |
| `KEEP_AWAKE=true` | 執行期間不讓電腦睡（見第 5 點） |

另外加了 `/health`（以前只有 `/api/health`）：醫院端的連線測試習慣是用手機瀏覽器打開
`https://主機:9443/health`。回應裡多了 `"service": "kidney-diet"`——因為原本那套 FastAPI
也用 9443，看到這個名字才能確定**接電話的是我們**，不是舊的那套還開著。

### 2. 直接用醫院那一張憑證，而且啟動時先檢查

醫院端已經有一套 CA：`ca.crt` 是公開的（內建在 App 裡），`server.crt` / `server.key` 給後端用，
`ca.key` 離線保管。我們的後端**就用那一組 `server.crt` / `server.key`**，跟原本的 FastAPI 一樣。
好處是：

- 不會出現第二張 CA，App 只需要內建一張
- 醫院端的續簽流程完全不用改（「只換伺服器憑證，App 不用更新」這件事仍然成立）

憑證有問題時，手機那一端只會看到「無法連線」，看不出是什麼原因。所以後端**啟動時就先檢查**，
有問題直接拒絕啟動、在視窗裡用中文寫出原因：

| 狀況 | 後端怎麼反應 |
|---|---|
| 找不到 `server.crt` / `server.key` | 拒絕啟動，告訴你從哪裡複製 |
| `server.key` 跟 `server.crt` 不是同一組 | 拒絕啟動 |
| 憑證不是簽給 `PUBLIC_HOST` 那個 IP | 拒絕啟動（手機一定會拒絕這張憑證） |
| 憑證已經過期 | 拒絕啟動，提醒走續簽流程 |
| 憑證「還沒生效」 | 拒絕啟動，提醒**檢查電腦時間**（幾乎都是時鐘錯了，不是憑證錯了） |
| 剩不到 30 天過期 | 照常啟動，但提醒續簽 |
| port 被佔用 | 拒絕啟動，提醒「舊的那套後端是不是還開著」，建議備用 port 18443 / 28443 |
| port 被 Windows 保留 | 拒絕啟動，說明這台的 8443/8080/8000 都不能用 |

### 3. 病人帳號：只有研究編號，只有衛教師能建

**以前**：病人自己用 email 註冊，要填姓名；`/api/auth/register` 任何人都能呼叫。
在醫院的訪客 Wi-Fi 上，任何拿到 APK 的人都能開帳號、上傳照片到研究資料庫。

**現在**：

| 誰 | 怎麼做 |
|---|---|
| **衛教師** | 登入 App →「我的」→「🧑‍⚕️ 衛教師工具」→「幫病人建帳號」，只填**研究編號**（例如 P0012）和初始密碼。**沒有姓名欄位**——少一個欄位，就少一個有人順手把名字打進去的機會 |
| **病人** | 用研究編號 + 密碼登入（衛教師通常直接在病人手機上幫他登入，登入狀態維持一年） |
| **伺服器** | 不存姓名、病歷號、email。資料庫欄位叫 `patient_ref`，跟醫院那套系統同名，日後兩邊資料對照不用轉換 |
| **路人** | 拿到 APK 也開不了帳號：自己註冊一律回「帳號由衛教師建立，請洽衛教師」 |

幾個細節：

- **全形轉半形**：長輩用注音輸入法很容易打出「Ｐ００１２」，看起來一模一樣、字元卻完全不同，
  會一直登不進去而且看不出原因。現在全形、小寫、中間有空白都會自動轉成 `P0012`。
- **舊的不會壞**：這個版本之前用 email 註冊的帳號照樣能登入；已經裝在護理師手機上的舊版 App
  （送的欄位叫 `email`）也照樣能登入。
- **衛教師帳號只能在主機上建**（`6_staff_account.bat create-staff`），沒有對應的 API——
  否則就等於有一條「從網路上變成衛教師」的路。
- **忘記密碼**：衛教師在「衛教師工具 → 協助重設密碼」輸入研究編號開代碼，流程跟以前一樣，只是不用再輸入 email。

### 4. 修掉一個「只有在醫院才會出現」的安全漏洞

這一點比較抽象，但很重要。

後端會限制「同一個來源 15 分鐘最多試 10 次登入」，防止有人一直猜密碼。問題是**怎麼判斷「同一個來源」**。

- **以前**（Render、Docker + Caddy）：後端躲在代理後面，看到的連線全部來自代理。代理會在請求上
  附一張紙條（`X-Forwarded-For`）寫「真正的來源是誰」，後端照著紙條算。這是對的，因為紙條是代理寫的。
- **醫院主機**：前面**沒有代理**，手機直接連到後端。如果後端還是相信那張紙條，**紙條就是攻擊者自己寫的**——
  每次請求換一張「我是另一個人」，限流就形同虛設。

研究編號又是 P0001、P0002 這種流水號，等於帳號是公開的、只剩密碼在擋。這個組合讓漏洞變得很實際。

**現在**：後端自己提供 HTTPS 時，自動不相信那張紙條（`TRUST_PROXY` 預設 `false`）。
實測：每次都換假紙條，第 11 次登入嘗試照樣被擋。把這個修正拿掉重測，連續 21 次都沒被擋。

順帶也補了另一個洞：以前「帳號不存在」會在 **1 毫秒**內回應、「密碼錯」要 **63 毫秒**（實測），
光看回應速度就能知道哪些研究編號已經收案。現在兩者花一樣久、回一樣的話。

### 5. 電腦睡著，病人就傳不上來

那台是醫師的診間電腦，支援睡眠。醫師去吃午餐、半小時後電腦睡著，候診區的病人怎麼按都傳不上來，
而且看起來跟「沒有網路」一模一樣，沒人會想到是電腦睡了。

**現在**：後端執行期間會跟 Windows 說「不要睡」（跟播影片時電腦不會睡是同一個機制）。

- **不需要系統管理員**、**不改任何電源設定**——後端一關，這個要求就自動消失
- 螢幕照樣會關，只是系統不睡
- 實測：執行前系統狀態「可以睡」、執行中「不可以睡」、結束後恢復「可以睡」

如果那台電腦的資安政策禁止這個機制，後端會印一行警告、照常運作；那時要請資訊室把睡眠設成「永不」。

### 6. 一個解壓縮就能跑的安裝包

在開發機上執行 `node deploy/windows/build-bundle.mjs`，會產生一個約 106 MB 的 zip，
裡面已經有那台電腦需要的一切：可攜版 `node.exe`、編譯好的後端、所有套件（包含 Windows 版的原生檔）。
**在醫院主機上不需要網路、不需要系統管理員、不需要安裝任何東西。**

裝好之後的資料夾長這樣：

```
%USERPROFILE%\kidney\
  app\        ← 程式。更新時整個刪掉、重新解壓縮都沒關係
  config\     ← kidney.env（port、憑證位置、JWT 密鑰）
  certs\      ← server.crt / server.key / ca.crt（從醫院原本那套後端複製來）
  data\       ← kidney.db 與照片。**這是病人資料，絕對不能刪**
  backups\    ← 備份
  logs\       ← 每天一個 log 檔
```

**程式和資料刻意分開放**：醫院端已經發生過一次整個資料夾遺失的事。程式在 `app\` 裡面、資料在外面，
更新時就算有人先把 `app\` 刪掉，資料也不會跟著不見。安裝包裡**沒有**任何設定、密鑰、憑證或資料，
所以可以放心交給別人，也不怕覆蓋掉主機上的東西。

操作腳本跟醫院原本那套用**同一套編號**，同一個人能操作兩套：

| 腳本 | 做什麼 | 要系統管理員 |
|---|---|---|
| `1_check_env.bat` | 檢查這台電腦準備好了沒（憑證、port、防火牆、電源、磁碟、IP 有沒有變） | |
| `2_firewall_open.bat <病人 Wi-Fi 網段>` | 開防火牆，**只開給病人 Wi-Fi 網段、只開給我們的 node.exe**；拒絕 `any` | ✅ |
| `2b_firewall_close.bat` | 關掉上面那條規則 | ✅ |
| `4_setup.bat` | 第一次安裝、以及每次更新後跑一次：建資料夾、產生設定與密鑰、建立/更新資料庫 | |
| `5_run.bat` | 啟動後端（視窗保持開著） | |
| `6_staff_account.bat` | 建衛教師帳號、改權限、看收了多少帳號與紀錄 | |
| `7_smoke_test.bat` | 用 `ca.crt` 驗證憑證，從外面打一次後端 | |
| `8_backup.bat` | 備份資料庫與照片（後端開著也可以） | |
| `9_autostart_on.bat` / `9b_autostart_off.bat` | 登入 Windows 時自動啟動（**核准後才用**） | |
| `10_verify_closed.bat` | 測試結束後確認防火牆、後端、自動啟動都關了 | |

醫院那套的 `3_reach_test` 我們不需要：後端的 `/health` 就是連線測試頁。

兩個不太起眼、但會擋住人的細節：

- **腳本裡只有英文**：那台電腦的主控台是 Big5（MS950），`.bat` 裡有中文會變亂碼甚至執行錯誤
  （醫院原本的腳本也是英文，同樣的原因）。中文說明在 Node 寫的工具裡，那邊顯示正常。
- **防火牆的封鎖規則**：後端第一次啟動時，Windows 會問「允許 node.js 存取網路嗎？」。
  不是系統管理員按不了「允許」，Windows 就**自動建立封鎖規則**，而封鎖規則會蓋過資訊室開的允許規則。
  這是我在開發機上實測時真的發生的事。所以 `2_firewall_open.bat` 會**先清掉這些封鎖規則**再建立允許規則，
  `1_check_env.bat` 也會偵測並提醒。

### 7. App 端：只信任醫院的 CA

醫院端送資訊室的資安措施寫的是「HTTPS + App 憑證鎖定」。現在 App 對醫院主機這個位址，
**只接受醫院 CA 簽的憑證**，連手機系統內建的公開 CA 都不接受——就算有人在院內網路架一台假伺服器、
拿到一張公開 CA 簽的憑證，App 也不會理它。其他網址維持系統預設。

麻煩的地方在於：**repo 是公開的**，醫院主機的 IP 與 CA（上面有醫院名稱）不能進版控。所以：

- 進版控的永遠是「不含任何醫院資訊」的預設設定
- 打包醫院版 APK 時，`frontend/scripts/hospital-apk.mjs apply` 從一個不進版控的設定檔
  （`deploy/hospital.local.json`）暫時放進醫院的 IP 與 CA，打包完 `restore` 換回來
- **忘記換回來，前端測試就會失敗**，避免把醫院資訊 commit 出去
- 這支腳本也會擋下常見的拿錯檔案：把 `server.crt` 當成 `ca.crt`、或檔案裡夾帶了私鑰

### 8. 順手修掉的：`grant-role` 已經壞了 12 天

建立衛教師帳號唯一的方法 `npm run grant-role`，從 10/06 改用 SQLite 那天起就**一執行就當掉**
（它引用了 SQLite 版本已經不存在的東西）。因為那支腳本不在型別檢查的範圍內，當時沒有被發現。
現在改寫成帳號工具（`npm run account`，`grant-role` 仍可用），而且放在會被型別檢查的地方，不會再默默壞掉。
關閉公開註冊之後，這支工具成了建立第一個衛教師帳號的唯一方式，所以這次一定要修。

## 三、怎麼驗證的

**不是只讀程式碼。** 每一項都實際跑過：

| 驗證 | 結果 |
|---|---|
| 新的醫院設定檢查（`npm run check:hospital`）：用一張測試用 CA，以跟醫院主機完全相同的設定啟動後端，從外面打 | **37 / 37** |
| 既有的忘記密碼檢查（`npm run check:password-reset`，含惡意情境） | **36 / 36** |
| 前端自動化測試 | **188 項**（新增 4 項：防止醫院資訊被 commit） |
| **變異測試**：故意把 6 個安全相關的地方改壞，確認檢查真的會失敗 | **6 / 6 都被抓到** |
| 資料表遷移：在一份**塞了紀錄、token、點數、徽章**的資料庫副本上跑 | 每張表筆數完全相同、外鍵 0 錯誤 |
| 離線安裝包：在全新資料夾解壓縮、模擬斷網，依序跑 1→10 號腳本 | 全部正常；`4_setup` 4 秒完成 |
| 防睡眠：用 Windows API 讀系統狀態（不需要管理員） | 執行前可睡 → 執行中不可睡 → 結束後可睡 |
| 瀏覽器實測新畫面（375×667） | 登入頁、衛教師工具、建帳號、重設代碼、病人首頁與個人頁：**全部不需要滑動** |

變異測試的細節（每一項都是「拿掉這個保護 → 對應的檢查變成失敗」）：

| 拿掉的保護 | 被哪個檢查抓到 |
|---|---|
| 不相信 X-Forwarded-For | 換假紙條連續 21 次都沒被擋 |
| 關閉公開註冊的開關 | 路人可以自己註冊 |
| 衛教師角色檢查 | 病人可以建帳號 |
| 帳號不存在時也比對密碼 | 回應時間 1 毫秒，洩漏編號是否存在 |
| 全形轉半形 | 全形的研究編號登不進去 |
| 檢查憑證是不是簽給這個 IP | 簽錯 IP 的憑證照樣啟動 |

過程中，變異測試也抓到**我自己檢查腳本的一個缺陷**：「應該拒絕啟動」的檢查，在伺服器其實成功啟動時
會一直等下去，而不是判定失敗。已經修正（最多等 20 秒，還活著就算失敗）。

## 四、還沒驗證、或需要決定的事

這一節最重要，請不要跳過。

### 需要在實際環境確認的

1. **實體 Android 手機**：App 對「IP 位址」的憑證鎖定設定、以及 WebView 是否遵守它，理論上 Android 7
   以上都支援，但**沒有在真的手機上試過**。相機、存相簿、完全離線冷啟動也一樣還沒實測。
2. **醫院主機上實際跑一次**：所有驗證都是在開發機上模擬的（同樣是 Windows x64、非系統管理員）。
3. **`2_firewall_open.bat` 的系統管理員流程**：我沒有系統管理員權限，**這支腳本建立與清除規則的部分沒有實際執行過**。
   只驗證了「不是系統管理員時會擋下來」。第一次在主機上用時，請跑完 `1_check_env.bat` 確認規則正確。
4. **訪客 Wi-Fi 是不是 NAT**：如果所有手機從主機看起來都是**同一個 IP**，「同一個來源 15 分鐘 10 次登入」
   就會變成全部病人共用。實際影響不大（登入狀態維持一年，病人很少需要登入），但收案當天衛教師連續幫很多人登入時可能會碰到。
   請問資訊室，或在現場測一次。

### 需要老師或 IRB 決定的

5. **手機上的資料沒有加密**。醫院文件寫「手機沒連上主機時，資料加密存在手機本地」——我們現在是存在
   App 的本機資料庫，**沒有另外加密**。這需要另外實作（App 端的工作，不在這次範圍）。
6. **Android 自動備份**：App 目前設定 `allowBackup="true"`，手機可能會把 App 的資料（包含還沒上傳的照片）
   備份到病人的 Google 帳號。要不要關掉、要不要寫進同意書，請 IRB 判斷。（關掉只要改一個設定）
7. **自動啟動要有人登入 Windows 才會跑**。這台電腦如果半夜被強制重開機，要等醫師早上登入後端才會回來。
   要做到「沒人登入也會啟動」需要系統管理員建排程工作，請資訊室協助。

### 上線前一定要做的

8. **先關掉原本那套 FastAPI 後端**（兩套都用 9443）。`1_check_env.bat` 會提醒 port 被佔用。
9. 醫院端文件第 8 節的事項仍然適用：**IRB、知情同意、BitLocker 磁碟加密、定期備份**。
   `8_backup.bat` 只是把備份放在同一台電腦上，**一定要再複製到別的地方**（有加密的外接硬碟）。

## 五、上線步驟（給操作的人）

**在開發機上**

1. `node deploy/windows/build-bundle.mjs` → 產生 `release\kidney-hospital-<版本>.zip`
2. 建 `deploy/hospital.local.json`（不會進版控）：`{ "host": "<主機 IP>", "port": 9443, "caCert": "<ca.crt 路徑>" }`
3. 打包醫院版 APK：
   ```
   cd frontend
   node scripts/hospital-apk.mjs apply
   npm run build:hospital
   npx cap sync android
   （到 D:\kidney-build\frontend\android 執行 .\gradlew.bat assembleDebug）
   node scripts/hospital-apk.mjs restore    ← 一定要換回來
   ```

**在醫院主機上**（用醫師同意的那個 Windows 帳號）

1. 關掉原本那套 FastAPI 後端
2. 把 zip 解壓縮到 `%USERPROFILE%\kidney\`（會出現 `app` 資料夾）
3. 從醫院原本那套後端的 `backend\certs\` 複製 `server.crt`、`server.key`、`ca.crt` 到 `%USERPROFILE%\kidney\certs\`
   （**不要**複製 `ca.key`）
4. `1_check_env.bat` → `4_setup.bat` → `5_run.bat`
5. 另開一個視窗：`7_smoke_test.bat`，應該看到「全部通過」
6. `6_staff_account.bat create-staff <衛教師 email> <密碼> <名字>` 建第一個衛教師帳號
7. 資訊室開通之後：用系統管理員執行 `2_firewall_open.bat <病人 Wi-Fi 網段>`，
   再用手機（連病人 Wi-Fi）的瀏覽器打開 `https://<主機 IP>:9443/health`
   ——會跳憑證警告是正常的（瀏覽器不認得醫院的 CA，只有 App 認得），看得到警告頁就代表網路通了
8. 測試結束：關掉 `5_run.bat` 的視窗 → 系統管理員執行 `2b_firewall_close.bat` → `10_verify_closed.bat` 應該是 ALL CLEAR

**更新程式**：關掉後端 → 刪掉 `app` 資料夾 → 解壓縮新的 zip → `4_setup.bat`（會套用資料庫變更）→ `5_run.bat`。
`config`、`certs`、`data` 都不用動。
