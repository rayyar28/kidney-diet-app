# 部署指南：把 App 送到病人手機上

專案：`rayyar28/kidney-diet-app`
情境：學校電腦自架 + Cloudflare Tunnel、30 人以上、3 個月以上
撰寫日期：2026-09-14

---

## 0. 先處理一個會讓整個計畫失敗的問題

你選的是「免費子網域」，但這個組合**實際上不成立**，必須先解決。

Cloudflare Tunnel 有兩種模式：

| 模式 | 網址 | 能不能用 |
|---|---|---|
| Quick Tunnel（免費、不用網域） | `https://random-words-here.trycloudflare.com` | ❌ **每次重啟都會換一組新網址** |
| Named Tunnel（需要一個在 Cloudflare 上的網域） | `https://app.你的網域.com` | ✅ 固定不變 |

問題在於：PWA 一旦被病人「加入主畫面」，那個圖示就**綁死在當時的網址**上。網址一變，病人點開會看到錯誤頁面，而且 30 個人你要一個一個重新教他們裝一次。學校電腦在三個月內一定會重開機（Windows 更新、停電、有人踢到插頭），Quick Tunnel 的網址就會跟著換。

DuckDNS 之類的免費動態 DNS 也解決不了，因為那需要你的機器有對外開放的 80/443 port，而學校網路幾乎都會擋。

**解法：買一個網域。** `.xyz` 或 `.app` 第一年約 NT$50–300，`.com` 約 NT$400。Cloudflare Registrar 本身就是成本價，不加價。這是整個部署裡唯一非花不可的錢，而它換來的是三個月內網址不會變。

以下步驟假設你已經有一個網域，我用 `kidney.example.com` 代稱，請自行替換。

## 1. 整體架構

```
病人手機 (4G/Wi-Fi)
      │  HTTPS
      ▼
Cloudflare 邊緣節點        ← TLS 憑證由 Cloudflare 自動處理，你不用管
      │
      │  加密隧道（由你的電腦「主動向外」建立）
      │  ★ 學校防火牆不需要開任何 port，也不需要固定 IP
      ▼
學校電腦
 └─ cloudflared（Tunnel 客戶端，開機自動啟動）
      │
      ▼  http://localhost:8080
 └─ Docker Compose
      ├─ caddy      :8080   ← 反向代理：/api/* → backend，其餘 → 前端靜態檔
      ├─ backend    :4000   （不對外）
      ├─ db         :5432   （不對外）
      └─ volumes: uploads_data, db_data
```

重點：**Tunnel 是由你的電腦主動向外連**，所以不需要跟學校網管申請開 port、不需要固定 IP、也不會暴露你的機器。這是在校園網路裡自架服務最乾淨的做法。

## 2. 程式碼要先改的五件事

目前 repo 裡沒有任何正式環境的建置路徑，以下檔案要新增或修改。

### 2.1 `frontend/Dockerfile` — 目前跑的是開發伺服器

現況是 `CMD ["npm", "run", "dev"]`，那是 Vite 的開發伺服器：沒有壓縮、沒有 minify、會暴露原始碼、效能差好幾倍，而且 Service Worker 不會正確產生（PWA 裝不起來）。

改成兩階段建置，最後只留靜態檔：

```dockerfile
# frontend/Dockerfile
FROM node:20-bookworm-slim AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build          # 產出 dist/，含 Service Worker 與 manifest

FROM alpine:3.20 AS export
WORKDIR /dist
COPY --from=build /app/dist ./
```

（靜態檔交給下面的 Caddy 服務，所以這個 image 只需要把 `dist` 生出來。）

### 2.2 `backend/Dockerfile` + entrypoint — 改成正式建置與 `migrate deploy`

```dockerfile
# backend/Dockerfile
FROM node:20-bookworm-slim
RUN apt-get update -y && apt-get install -y --no-install-recommends openssl \
    && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npx prisma generate && npm run build
RUN chmod +x docker-entrypoint.prod.sh
EXPOSE 4000
ENTRYPOINT ["./docker-entrypoint.prod.sh"]
CMD ["node", "dist/index.js"]
```

```sh
#!/bin/sh
# backend/docker-entrypoint.prod.sh
set -e
echo "Applying migrations..."
npx prisma migrate deploy      # ★ 不是 migrate dev
exec "$@"
```

**為什麼一定要換掉 `migrate dev`**：`migrate dev` 偵測到資料庫與 migration 歷史不一致時，會要求重置整個資料庫。你收了三個月的病人資料，某次改 schema 就可能全部消失。`migrate deploy` 只會往前套用 migration，絕不重置。

另外注意：原本的 entrypoint 每次啟動都會跑 `seed.ts`。正式環境要把它拿掉，改成第一次部署時手動跑一次：

```bash
docker compose -f docker-compose.prod.yml exec backend npx tsx prisma/seed.ts
```

（如果 seed 裡的徽章建立不是用 `upsert`，重複執行會失敗或產生重複資料，順手檢查一下。）

### 2.3 新增 `Caddyfile`

```
:8080 {
    encode gzip zstd

    handle /api/* {
        reverse_proxy backend:4000
    }

    handle {
        root * /srv
        try_files {path} /index.html    # SPA 路由需要
        file_server
    }

    # Service Worker 不可被快取，否則病人會卡在舊版
    @sw path /sw.js /registerSW.js
    header @sw Cache-Control "no-cache, no-store, must-revalidate"

    header /assets/* Cache-Control "public, max-age=31536000, immutable"
}
```

### 2.4 新增 `docker-compose.prod.yml`

```yaml
services:
  db:
    image: postgres:16-alpine
    restart: always
    environment:
      POSTGRES_USER: kidney_app
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}   # ← 從 .env.prod 讀，不寫死
      POSTGRES_DB: kidney_diet
    volumes:
      - db_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U kidney_app"]
      interval: 10s
      timeout: 5s
      retries: 10
    # ★ 注意：沒有 ports:，資料庫完全不對外

  backend:
    build: ./backend
    restart: always
    env_file: ./backend/.env.prod
    volumes:
      - uploads_data:/app/uploads
    depends_on:
      db: { condition: service_healthy }
    # ★ 同樣沒有 ports:，只有 caddy 進得來

  frontend-build:
    build: ./frontend
    volumes:
      - frontend_dist:/dist-out
    command: sh -c "cp -r /dist/. /dist-out/"

  caddy:
    image: caddy:2-alpine
    restart: always
    ports:
      - "127.0.0.1:8080:8080"     # ★ 只綁 localhost，只有 cloudflared 連得到
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - frontend_dist:/srv:ro
      - caddy_data:/data
    depends_on:
      - backend
      - frontend-build

volumes:
  db_data:
  uploads_data:
  frontend_dist:
  caddy_data:
```

與開發版的差別，每一項都有理由：

- **沒有 source code 的 volume mount** — 開發版把 `./backend/src` 掛進容器是為了熱重載，正式環境要用 image 裡建置好的版本
- **`db` 和 `backend` 都沒有 `ports:`** — 只有同一個 Docker network 內的服務連得到
- **`caddy` 的 port 綁 `127.0.0.1`** — 就算學校電腦被掃 port 也看不到東西
- **`restart: always`** — 停電或重開機後自動回來

### 2.5 `backend/.env.prod`（**絕對不要 commit**）

```bash
DATABASE_URL="postgresql://kidney_app:這裡放真的隨機密碼@db:5432/kidney_diet?schema=public"
JWT_ACCESS_SECRET="..."      # 見下方產生方式
JWT_REFRESH_SECRET="..."
JWT_ACCESS_EXPIRES_IN="15m"
JWT_REFRESH_EXPIRES_IN="30d"
UPLOAD_DIR="/app/uploads"
PORT=4000
CORS_ORIGIN="https://kidney.example.com"   # ★ 改成你的正式網址
```

產生隨機值（PowerShell）：

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

跑三次，分別給兩個 JWT secret 和資料庫密碼。**現在 repo 裡的 `.env` 是開發用的，正式環境必須換成新的**——開發用的那份可能在截圖、報告、跟同學的對話裡出現過。

同時確認 `.gitignore` 有擋 `.env.prod`（目前的 `.env` 規則不會擋到 `.env.prod`，要另外加一行）。

## 3. Cloudflare Tunnel 設定步驟

### 3.1 把網域接到 Cloudflare

1. 註冊 Cloudflare 免費帳號
2. Add a site → 輸入你的網域
3. 照指示把網域的 Nameserver 改成 Cloudflare 給的兩組（在你買網域的地方改）
4. 等生效，通常幾分鐘到幾小時

### 3.2 安裝 cloudflared 並建立 Tunnel

在學校電腦上（PowerShell，系統管理員）：

```powershell
winget install --id Cloudflare.cloudflared

cloudflared tunnel login          # 會開瀏覽器要你授權
cloudflared tunnel create kidney-app
# 記下輸出的 Tunnel ID 與憑證檔路徑
cloudflared tunnel route dns kidney-app kidney.example.com
```

建立設定檔 `C:\Users\<你>\.cloudflared\config.yml`：

```yaml
tunnel: kidney-app
credentials-file: C:\Users\<你>\.cloudflared\<TunnelID>.json

ingress:
  - hostname: kidney.example.com
    service: http://localhost:8080
  - service: http_status:404
```

### 3.3 設成開機自動啟動的 Windows 服務

```powershell
cloudflared service install
```

這一步很重要。如果只是開一個終端機跑 `cloudflared tunnel run`，那個視窗被關掉或電腦重開，病人的 App 就斷線了。

### 3.4 啟動並驗證

```powershell
cd D:\大學\專題\claude_app
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec backend npx tsx prisma/seed.ts
```

用**手機的 4G**（不要用學校 Wi-Fi，那樣測不出來）開 `https://kidney.example.com`，應該要看到登入頁，網址列有鎖頭。

## 4. 學校電腦連續運行三個月的現實問題

這是你這個方案最大的風險，每一項都建議先處理：

| 風險 | 會發生什麼 | 處理方式 |
|---|---|---|
| **Windows 自動更新重開機** | 半夜重開，Docker Desktop 沒自動啟動，隔天早上病人全部上傳失敗 | 設定「使用中時間」涵蓋全天；Docker Desktop 開啟「Start when you log in」；Windows 設定自動登入（`netplwiz`） |
| **電腦睡眠 / 休眠** | Tunnel 斷線 | 電源選項改成「永不睡眠」，包含硬碟和網路卡的節能設定 |
| **停電** | 資料庫可能損毀 | 至少接一台便宜的 UPS（約 NT$2,000），撐得過短暫停電並安全關機 |
| **有人關機或拔網路線** | 服務中斷數小時到數天 | 機器貼紙條寫「研究進行中，請勿關機」；設一個外部監測（見下） |
| **學校網路維護 / 寒暑假斷網** | 同上 | 事先問系辦的維護時間表 |

**建議加一個外部監測**：用 UptimeRobot（免費）每 5 分鐘打一次 `https://kidney.example.com/api/health`，掛掉就寄信給你。你的後端已經有這支 endpoint 了。不然你可能三天後才從病人的抱怨中發現服務掛了——而那三天的資料永遠補不回來。

## 5. 備份：三個月研究的生死問題

**一台電腦上的資料等於沒有備份。** 硬碟壞掉、勒索軟體、誤刪一個 volume，三個月的收案就沒了，而且無法重來。

建立 `backup.ps1`，用工作排程器設每天凌晨執行：

```powershell
$date = Get-Date -Format "yyyyMMdd"
$dest = "E:\kidney-backup"          # ← 另一顆實體硬碟，不是同一顆的別的分割區
New-Item -ItemType Directory -Force -Path "$dest\$date"

# 1. 資料庫
docker compose -f docker-compose.prod.yml exec -T db `
  pg_dump -U kidney_app kidney_diet | Out-File -Encoding utf8 "$dest\$date\db.sql"

# 2. 照片
docker run --rm -v claude_app_uploads_data:/data -v "${dest}\${date}:/backup" `
  alpine tar czf /backup/uploads.tar.gz -C /data .

# 3. 保留 30 天
Get-ChildItem $dest | Where-Object {
  $_.CreationTime -lt (Get-Date).AddDays(-30)
} | Remove-Item -Recurse -Force
```

再加一份異地備份。**但醫療資料傳到雲端前必須加密**：

```powershell
# 用 7-Zip 加密後再上傳（密碼另外保管，不要跟檔案放一起）
& "C:\Program Files\7-Zip\7z.exe" a -tzip -p"密碼" -mem=AES256 `
  "$dest\$date.zip" "$dest\$date\*"
```

**每個月至少實際還原一次**，確認備份檔真的能用。沒有驗證過的備份不算備份——這是研究資料管理最常見的翻車點。

## 6. 儲存空間估算與照片壓縮

**不壓縮的話**（目前的實作，原圖直接存）：

```
30 人 × 3 餐 × 2 張 × 3MB ≈ 540 MB / 天
90 天 ≈ 48 GB
如果收 50 人或延長到半年 → 150 GB 以上
```

**壓縮後**（長邊 2048px、JPEG quality 85）：

```
每張約 400–800 KB，總量降到 1/4 左右
30 人 × 90 天 ≈ 12 GB
```

2048px 對之後跑營養辨識完全夠用（大多數影像模型的輸入是 224–512px），但檔案小四倍，備份和傳輸都輕鬆很多。

而且這個改動可以**一次解決我上次報告裡的四個問題**，都在 `photo.service.ts` 的同一個地方：

```ts
// 1. 先讀 EXIF（研究用：真正的拍攝時間、判斷是不是現拍）
const meta = await sharp(photo.buffer).metadata();
// → exifCapturedAt, exifRaw, captureSource

// 2. rotate() 套用 EXIF 方向 → 修正 widthPx/heightPx 記錯的問題
// 3. withMetadata({ exif: {} }) → 清掉 GPS 座標
// 4. resize + 產生縮圖 → 解決儲存空間與歷史頁載入速度
const processed = await sharp(photo.buffer)
  .rotate()
  .resize(2048, 2048, { fit: "inside", withoutEnlargement: true })
  .jpeg({ quality: 85 })
  .withMetadata({ exif: {} })
  .toBuffer();

const thumb = await sharp(photo.buffer)
  .rotate()
  .resize(512, 512, { fit: "inside" })
  .jpeg({ quality: 75 })
  .withMetadata({ exif: {} })
  .toBuffer();
```

搭配 schema 加上 `thumbnailStorageKey`、`exifCapturedAt`、`exifRaw`、`captureSource`、`exifOrientation` 這幾個欄位。

## 7. 病人端：怎麼把 App 裝到手機上

### Android（Chrome）

1. 用 **Chrome** 開啟 `https://kidney.example.com`
2. 畫面下方通常會自動跳出「安裝應用程式」的橫幅 → 點「安裝」
3. 沒跳出來的話：右上角 ⋮ → 「安裝應用程式」或「加到主畫面」
4. 桌面出現圖示，點開就是全螢幕

⚠️ 小米、OPPO、vivo 等廠商的系統會積極清背景程式，可能影響提醒通知。請病人在「電池設定」中把這個 App 設為「不受限制」。

### iOS（Safari）

1. **一定要用 Safari**（用 Chrome 開會裝不起來或行為不一致）
2. 開啟 `https://kidney.example.com`
3. 點下方中間的「分享」按鈕（方框加向上箭頭）
4. 往下滑，選「加入主畫面」
5. 點「新增」

⚠️ iOS 的注意事項：

- **Web 推播需要 iOS 16.4 以上**，而且必須是已加入主畫面的狀態。更舊的 iPhone 收不到餐後提醒。
- iPhone 儲存空間不足時，系統可能清掉 PWA 的 localStorage，**病人會突然被登出**。所以：

### 建議的收案流程

1. **帳號由你預先建立**，不要讓病人自己註冊。你的 `SECURITY_AUDIT.md` 已經指出目前沒有 email 驗證機制，任何人都能用任意 email 註冊——正式收案時這會讓陌生人的資料混進你的研究資料集。
2. 準備一張**紙本帳密卡**給每位病人（名片大小），上面印：網址、帳號、密碼、以及安裝步驟的截圖。被登出時他們才有辦法自己登回來。
3. **當場幫他裝一次**，並請他現場拍一餐完整的餐前+餐後，確認整個流程走得通。這一步不能省——遠端教長輩裝 PWA 幾乎不可能成功。
4. 留一個 LINE 或電話讓他們遇到問題時找得到你。

## 9. 一個值得考慮的替代方案

你選學校電腦是為了省錢，這完全合理。但考量到「30 人以上、3 個月以上」是**不能中斷、資料遺失無法重來**的正式收案，值得算一下另一筆帳：

一台最便宜的 VPS（2 核 2GB、50GB 磁碟）約 NT$200–300/月，三個月不到 NT$1,000。換來的是：不會有人關機、機房有備援電力、有快照備份、不用煩惱 Windows 更新。

如果學校有補助研究經費，或你把它當成「三個月資料的保險費」，這個錢可能比你想像中划算。混合做法也可以：**主機跑在 VPS，學校電腦只當備份目的地**，兩邊的優點都拿到。
